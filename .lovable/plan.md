# Проверка Environment Settings в Dokploy

На скриншоте две ошибки, из-за которых заявки не будут отправляться.

## 1. Лишние угловые скобки в токене

Сейчас:

```text
TELEGRAM_BOT_TOKEN=<8604500241:AAGp-...>
```

Символы `<` и `>` — это placeholder из инструкции, они попадут в значение, и
Telegram вернёт `401 Unauthorized`. Нужно без скобок:

```text
TELEGRAM_BOT_TOKEN=8604500241:AAGp-...
```

## 2. Дублированная строка PORT

Сейчас: `PORT=5173PORT=5173` — это одно значение `5173PORT=5173`, сервер не
сможет разобрать порт. Должно быть одной строкой:

```text
PORT=5173
```

## Итоговый корректный блок

```text
TELEGRAM_BOT_TOKEN=8604500241:AAGp-...(без скобок)
TELEGRAM_CHAT_ID=8947129651
PORT=5173
```

`TELEGRAM_CHAT_ID` указан верно.

## 3. Токен нужно перевыпустить

Токен виден в переписке и раньше был в публичном бандле сайта, то есть считается
скомпрометированным. В @BotFather выполнить `/revoke` для бота, получить новый
токен и вписать только в Environment Settings (в код не добавлять).

## 4. Проверка после Deploy

1. Сохранить переменные, нажать Deploy (по возможности с Clean Build Cache).
2. Проверить эндпоинт:

```bash
curl -sS -X POST https://ddsmarket.ru/api/public/lead \
  -H 'content-type: application/json' \
  -d '{"name":"Тест","phone":"+7 999 000-00-00","message":"проверка","source":"curl"}'
```

Ожидаемо: `{"ok":true,"telegram":true,"email":"skipped"}` и сообщение в боте.
`502` — переменные не подхватились; HTML вместо JSON — деплой собрал старую версию.

## Изменения в коде

Не требуются: правки только в настройках Dokploy. Если после исправления
переменных заявки всё ещё не приходят, следующий шаг — посмотреть лог запуска
контейнера и ответ `curl`.
