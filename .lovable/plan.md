# Надёжный деплой сайта в Dokploy

Логи сборки чистые, значит проблема не в сборке, а в **раздаче готовых файлов**. Три вероятные причины в текущей конфигурации:

1. Стартовая команда `caddy file-server --listen 0.0.0.0:${PORT:-3000}` — если Dokploy не передаёт переменную `PORT`, Caddy слушает 3000, а прокси стучится в 5173, и наружу сайт не отвечает (при этом в логах ошибок нет).
2. У `caddy file-server` нет SPA-фолбэка: любой путь кроме `/` может отдавать 404.
3. Nixpacks-образ зависит от того, попал ли `caddy` в рантайм-слой — это ненадёжно.

## Что сделаю

Перевожу деплой на **Dockerfile** — детерминированный вариант, который Dokploy понимает без магии Nixpacks.

- `Dockerfile`: этап сборки на Bun (`bun install --frozen-lockfile`, `bun run build:pages`), затем рантайм на nginx:alpine с копированием `dist/client`.
- `nginx.conf`: слушает порт **5173** (как настроено у тебя в Dokploy), SPA-фолбэк `try_files $uri $uri/ /index.html`, gzip, кэш-заголовки для `/assets/*`, правильные MIME для `.webp`, `.mp4`, `.woff2`.
- `.dockerignore`: исключает `node_modules`, `dist`, `.git` — сборка быстрее и без мусора.
- `nixpacks.toml` привожу к рабочему виду на случай, если ты останешься на Nixpacks: старт через Node-скрипт с SPA-фолбэком и `process.env.PORT`, без зависимости от Caddy.

## Что нужно от тебя после синхронизации

1. Push изменений в `main`.
2. В Dokploy: Build Type → **Dockerfile**, путь `./Dockerfile`.
3. Порт приложения — **5173**, Build/Start overrides очистить.
4. Redeploy → Clear Build Cache.

## Проверка

Локально соберу образ не смогу (в песочнице нет Docker), но проверю:
- `bun run build:pages` проходит и `dist/client/index.html` + `404.html` на месте;
- конфиг nginx синтаксически корректен (по эталонному шаблону);
- ключевые страницы (`/`, `/catalog`, карточка товара) есть в пререндере.
