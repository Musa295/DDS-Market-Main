# Исправление деплоя DDS Market в Dokploy

## Что обнаружено

- Клонирование GitHub проходит успешно.
- В фактической сборке Dokploy используется старый `nixpacks.toml`: `npm ci`, запуск `npx serve dist -s -p 5173`.
- В репозитории есть `bun.lock`, а готовая статическая сборка проекта создаётся командой `build:pages` в каталоге `dist/client`.
- `Bad Gateway` возникает после сборки/старта контейнера; текущая команда запуска указывает не тот каталог и жёстко задаёт порт `5173` вместо порта Dokploy.

## План изменений

1. Обновить `nixpacks.toml`:
   - установить Node.js 20, Bun и Caddy;
   - выполнять `bun install --frozen-lockfile`;
   - собирать сайт командой `bun run build:pages`;
   - раздавать `dist/client` через Caddy на `0.0.0.0` и порту `${PORT:-3000}`.
2. Не менять страницы, каталог, дизайн и контент сайта.
3. Локально проверить установку по `bun.lock`, статическую сборку и наличие `dist/client/index.html`.
4. Запустить собранный сайт на тестовом порту и проверить главную страницу, каталог, карточку товара, изображения, видео и прямое открытие внутренних URL.
5. После отправки изменения в `main` повторно развернуть приложение в Dokploy без build cache и проверить, что контейнер остаётся запущенным и отвечает без `Bad Gateway`.

## Настройки Dokploy после обновления

- Builder: `Nixpacks`
- Branch: `main`
- Install/Build/Start overrides: оставить пустыми, чтобы использовался `nixpacks.toml`
- Environment: `PORT=3000` (или порт, автоматически заданный Dokploy)
- Internal/Container Port: тот же порт, обычно `3000`
- Redeploy: выполнить с очисткой build cache
