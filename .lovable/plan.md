# Проверка настроек Dokploy: всё исправлено

## Environment Settings — теперь верно

```text
TELEGRAM_BOT_TOKEN=8604500241:AAGp-...   ← без угловых скобок, ок
TELEGRAM_CHAT_ID=8947129651              ← ок
PORT=5173                                ← одна строка, ок
```

Обе прежние ошибки (скобки `<...>` вокруг токена и дубль `PORT=5173PORT=5173`)
устранены.

## Сообщения из лога — не ошибки

- `SecretsUsedInArgOrEnv` (TELEGRAM_BOT_TOKEN) — предупреждение сборщика о том,
  что секрет передаётся как переменная окружения образа. Сборку не ломает.
  В нашей схеме это нормально: токен нужен процессу в рантайме и в код не попадает.
- `UndefinedVar: $NIXPACKS_PATH` — стандартное предупреждение самого Nixpacks.
- `=== Successfully Built! === / ✅ Nixpacks build completed.` — сборка прошла.

Итог: сборка успешна, менять код или конфиги не требуется.

## Что осталось проверить (без изменений в коде)

1. Убедиться, что контейнер запущен и в логе есть строка
   `[serve] dist/client на http://0.0.0.0:5173`.
2. Проверить эндпоинт заявок:

```bash
curl -sS -X POST https://ddsmarket.ru/api/public/lead \
  -H 'content-type: application/json' \
  -d '{"name":"Тест","phone":"+7 999 000-00-00","message":"проверка","source":"curl"}'
```

Ожидаемо `{"ok":true,"telegram":true,"email":"skipped"}` и сообщение в боте.
`502` — переменные не подхватились контейнером; HTML вместо JSON — раздаётся
старая сборка, нужен Deploy с Clean Build Cache.

3. Отправить тестовую заявку через форму на странице «Контакты».

## Безопасность

Текущий токен ранее находился в публичном бандле сайта и виден в переписке,
поэтому его стоит перевыпустить: в @BotFather выполнить `/revoke`, новый токен
вписать только в Environment Settings.

## Изменения в коде

Не требуются. Если после проверки заявки не приходят — следующий шаг это
диагностика по ответу `curl` и логу запуска контейнера.
